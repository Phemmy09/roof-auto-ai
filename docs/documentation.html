Roof Auto AI

Automated roofing material order & crew documentation system for Reliable Exteriors Group. Processes job documents in under 2 minutes using Claude AI.

Next.js 16.2.4 Claude Sonnet 4.6 Supabase React 19 TypeScript 5

Project Overview

Roof Auto AI eliminates manual paperwork for roofing jobs. A user uploads job documents (Eagle View measurement reports, contracts, city/county code PDFs, site photos), and the system returns a fully calculated material order, crew instructions, labor items, and a PDF emailed to the designated recipient — all automatically.

Problem Solved

Manual material calculation and crew document creation takes hours per job and is error-prone.

Solution

AI extracts measurements from uploaded PDFs and calculates all material quantities via configurable formulas.

Target User

Reliable Exteriors Group — private, single-tenant application. Not public-facing.

Performance

End-to-end processing in 70–120 seconds per job. Job data auto-deleted from storage after 10 minutes.

What the system produces per job

  • Material Order Form — 12 calculated quantities (shingles, felt, ice & water, drip edge, pipe jacks, ridge vent, nails, sealant, etc.)
  • Crew Instructions — Ordered, site-specific steps based on jurisdiction, roof geometry, and contract type
  • Labor Items — Billable charge line items extracted from the scope
  • Material Notes — Color specs, supplement flags, code-required additions
  • PDF — Generated and emailed automatically to cheryl@therelexgroup.com

Architecture

Roof Auto AI is a monolithic Next.js full-stack application. All backend logic runs as Next.js API Routes on Vercel serverless functions. There is no separate backend server.

Key Design Decisions

  • Signed upload URLs — Files are uploaded directly from the browser to Supabase Storage using a signed URL, bypassing Vercel's 4.5 MB body size limit. Only the Supabase file path is sent to the API.
  • Single Claude call — Data extraction AND crew document generation happen in one API call, cutting processing time roughly in half.
  • No persistent job records — Files are stored in Supabase Storage for processing only. No job data is stored in the database. Storage cleanup is manual or via a cron job.
  • Configurable formula engine — Coverage constants (felt rolls/SQ, drip edge length, etc.) are stored in a singleton database row and editable via /formula-engine without code changes.

File Filtering Rules

Files whose names contain any of these patterns are excluded from the Claude API call (photos are noted in the job but not analyzed):

['before', 'progress', 'completion', 'after', 'photo', 'pic', 'image', 'drone']

Only PDFs, images, and plain text that pass this filter are sent to Claude. Individual files larger than 4 MB (non-image) are skipped with a warning. Images over 1.5 MB are automatically capped before encoding.

API Reference — POST /api/get-upload-url

Generates a signed Supabase Storage upload URL so the browser can upload files directly without going through the Next.js server (avoids Vercel's 4.5 MB body limit).

POST /api/get-upload-url

Request Body

{ "filename": "EagleView_Scarritt.pdf" }

Success Response

{
  "signedUrl": "https://oaohufpux...supabase.co/storage/v1/object/upload/sign/...",
  "token":     "eyJhbGci...",
  "path":      "jobs/1748123456789_EagleView_Scarritt.pdf"
}

Notes

  • Filename is sanitized: only [a-zA-Z0-9.\-_] characters allowed; others replaced with _
  • Path format: jobs/{timestamp}_{sanitizedName}
  • Retries up to 3 times on socket errors with exponential backoff (500ms → 1s → 2s)

API Reference — GET/PUT /api/formulas

Reads and writes the singleton formula configuration row from Supabase Postgres.

GET /api/formulas

Returns the current formula config. If the table is missing, returns hardcoded defaults with "source": "fallback". Never returns a 500 — always returns something usable.

{
  "success": true,
  "source":  "db",          // or "fallback" | "mock"
  "config": {
    "feltCoverage":     10,   // SQ per roll
    "iceWaterCoverage": 60,   // LF per roll
    "ridgeCapCoverage": 31,   // LF per bundle
    "dripEdgeLength":   10,   // LF per piece (stick)
    "coilNailsCoverage":12,   // SQ per case
    "enableFelt":       true,
    "enableIceWater":   true,
    "enableRidgeCap":   true,
    "enableDripEdge":   true,
    "enableCoilNails":  true
  }
}
PUT /api/formulas

Upserts the formula config using singleton_key = 'STATIC'. Returns 500 if the database table is missing (does not silently pretend to save).

// Request body: same shape as the "config" object above
{ "feltCoverage": 10, "iceWaterCoverage": 60, ... }

// Success response
{ "success": true, "config": { ... } }

Core Module — anthropic.ts

Location: src/lib/anthropic.ts

Handles all interaction with the Anthropic Claude API. Performs a single combined call that simultaneously extracts roof measurements from documents AND generates crew instructions, labor items, and material notes.

Key Function: processJobWithAI

async function processJobWithAI(documents: any[]): Promise<{
  extractedData:    any;       // 19 fields from documents
  crewInstructions: string[];  // ordered crew steps
  laborItems:       string[];  // billable charges
  materialNotes:    string[];  // supplement flags, color specs
}>

Behavior

  • Uses Claude Sonnet 4.6, max_tokens: 8192, temperature: 0 (deterministic)
  • System prompt embeds all business rules (crew instructions, code compliance, insurance scope mapping, material logic) from training-data.ts
  • Returns one JSON object from Claude with two sections: extracted and documents
  • If Claude's response is truncated (stop_reason: 'max_tokens'), attempts JSON repair by trimming to the last closing brace }
  • If the API key is a placeholder, returns a hardcoded mock response instead of calling the API
  • On API error, throws — allowing the caller (process-job) to return a proper 500 to the user

capImageBuffer

function capImageBuffer(buffer: Buffer): Buffer

Caps image buffers at 1.5 MB before base64 encoding. Large site photos are the primary cause of slow processing. PDFs are handled separately with a 4 MB skip threshold (not cap — truncating a PDF corrupts it).

Core Module — formulas.ts

Location: src/lib/formulas.ts

Pure calculation engine. Takes extracted measurements and the formula config and returns all 13 material quantities.

Core Module — pdf.tsx

Location: src/lib/pdf.tsx

Generates a 3-section PDF using @react-pdf/renderer (server-side React rendering). The PDF contains:

  1. Header with job info (customer, address, claim #, approved amount, deductible)
  2. Material Order Form — all 12 quantities in a formatted table
  3. Crew Instructions — numbered list
  4. Labor Items — numbered list

Uses renderToStream() (not renderToBuffer()) and collects stream chunks into a Buffer for email attachment.

Core Module — email.ts

Location: src/lib/email.ts

Sends the PDF via Nodemailer over Gmail SMTP. Configuration is driven entirely by environment variables.

Core Module — supabase.ts

Location: src/lib/supabase.ts

Exports a single supabaseAdmin client using the service role key (bypasses Row Level Security). autoRefreshToken and persistSession are both disabled since this is a server-only client.

Formula Engine

The Formula Engine page (/formula-engine) allows non-technical staff to adjust the coverage constants used in material calculations — without any code changes or developer involvement.

How to adjust a formula

  1. Navigate to /formula-engine
  2. Adjust the numeric value (e.g. change Felt Coverage from 10 to 4 for 15 LB felt paper)
  3. Toggle items on/off using the checkbox (e.g. disable Coil Nails if ordering separately)
  4. Click Save Changes
  5. The change persists to Supabase and takes effect immediately on the next job processed

Default Values

FieldDefaultUnitWhat to change it to
Felt Coverage10SQ per rollSet to 4 if using 15 LB felt paper (4 SQ/roll)
Ice & Water Coverage60LF per rollAdjust if using a non-standard roll size
Ridge Cap Coverage31LF per bundleCheck the product's LF rating per bundle
Drip Edge Length10LF per pieceStandard 10 ft sticks — rarely changes
Coil Nails Coverage12SQ per caseAdjust based on nail brand/size spec sheet

Database Schema

Only one table exists. Run docs/supabase_schema.sql in the Supabase SQL Editor to create it.

CREATE TABLE formula_config (
  id                 bigint       PRIMARY KEY GENERATED ALWAYS AS IDENTITY,
  singleton_key      text         UNIQUE NOT NULL DEFAULT 'STATIC',
  felt_coverage      numeric      NOT NULL DEFAULT 10,
  ice_water_coverage numeric      NOT NULL DEFAULT 60,
  ridge_cap_coverage numeric      NOT NULL DEFAULT 31,
  drip_edge_length   numeric      NOT NULL DEFAULT 10,
  coil_nails_coverage numeric     NOT NULL DEFAULT 12,
  enable_felt        boolean      NOT NULL DEFAULT true,
  enable_ice_water   boolean      NOT NULL DEFAULT true,
  enable_ridge_cap   boolean      NOT NULL DEFAULT true,
  enable_drip_edge   boolean      NOT NULL DEFAULT true,
  enable_coil_nails  boolean      NOT NULL DEFAULT true,
  updated_at         timestamptz  DEFAULT now()
);

-- Seed the singleton row
INSERT INTO formula_config (singleton_key) VALUES ('STATIC')
ON CONFLICT (singleton_key) DO NOTHING;

Vercel Deployment

  1. Push code to GitHub (main branch is auto-deployed)
  2. In Vercel → Settings → Environment Variables, add all 9 variables from the table above
  3. Set CORS_ORIGINS to your Vercel production URL (e.g. https://roof-auto.vercel.app)
  4. Ensure the Supabase Storage bucket roof-documents exists and has the service key granted full access
  5. Run docs/supabase_schema.sql in Supabase SQL Editor if the formula_config table doesn't exist yet
  6. Deploy — Vercel triggers automatically on push to main
⚠️
The process-job route sets maxDuration = 300. This requires Vercel Pro or higher. Hobby plans limit functions to 60 seconds, which is insufficient for AI processing.

Business Rules

All business logic is embedded in src/lib/training-data.ts as string constants that are injected into Claude's system prompt. This allows updating rules without changing application logic.

CREW_INSTRUCTION_RULES

Ventilation, I&W placement, flashing, tear-off, photography, safety, satellite/solar/skylight handling

CODE_COMPLIANCE_RULES

Priority: County code > Contract > Insurance. Mid-roof inspection thresholds, permit requirements, decking standards

INSURANCE_SCOPE_MAPPING

14 RFG insurance line item codes, exclusion rules, labor item categories

MATERIAL_LOGIC

Conditions for including each material, coverage ratios, product specs (step flashing, drip edge, etc.)

Troubleshooting

Job fails with "Claude AI error"

  • Check ANTHROPIC_API_KEY is valid and not expired
  • Verify account has sufficient credits at console.anthropic.com
  • Check Vercel function logs for the specific error message

Files fail to upload

  • Confirm the Supabase bucket roof-documents exists
  • Confirm SUPABASE_SERVICE_KEY (not the anon key) is used — service key bypasses RLS
  • Check that the bucket allows uploads from the service key (no restrictive RLS policy)

Email not delivered

  • Confirm Gmail 2FA is enabled and SMTP_PASS is an App Password (16 chars, spaces removed)
  • Verify SMTP_PORT=465 and SMTP_HOST=smtp.gmail.com
  • Check the Vercel function logs for the Nodemailer error code
  • Gmail may block "less secure app access" — App Passwords bypass this

Materials all show 0

  • Claude failed to extract measurements — check the notes field in extractedData
  • The EagleView PDF was not included in the upload, or was filtered as a photo (check filename doesn't contain "photo", "before", etc.)
  • The file was too large (>4 MB for PDFs) and was skipped — check Vercel function logs for "Skipping" warnings

Formula Engine shows "Error updating formulas"

  • The formula_config table doesn't exist — run docs/supabase_schema.sql in Supabase SQL Editor
  • The SUPABASE_SERVICE_KEY lacks write access to the table

Processing takes longer than 120 seconds

  • Contract PDF is very large — compress it before uploading (target <2 MB)
  • Too many files sent to Claude — remove duplicate documents
  • Check if site photos are accidentally passing the filename filter (rename to include "photo" or "before")
